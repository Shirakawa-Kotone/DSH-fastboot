# DSH Fastboot · 项目介绍动画分镜

## 规格

| 项 | 值 |
|---|---|
| 画幅 | 1920 × 1080（16:9，1080P） |
| 帧率 | 30 fps |
| 时长 | 114 s（3420 帧） |
| 编码 | H.264 / MP4， `yuv420p` |
| 语言 | 简体中文，代码与包名保留英文 |
| 声音 | 原创 100 BPM 合成配乐（底鼓/军鼓/踩镲/贝斯/琶音/铺底，Am–F–C–G）+ 转场 whoosh，无版权素材 |
| 工具 | Remotion 4 + React，Chrome Headless 逐帧渲染 |

## 视觉基调

- **画布**：近黑蓝 `#05070D`，叠加径向冷光（青 `#22D3EE` / 紫 `#8B5CF6`）与 48px 点阵网格；轻微噪点与扫描线，避免大面积死黑。
- **语法**：深色玻璃卡片、细描边、单色等宽代码、超大中文标题；所有强调色只服务信息，不做无意义霓虹。
- **动效**：弹簧入场（damping 200）、遮罩揭示、数字滚动、路径描边、纵向瀑布条；转场以 8–14 帧的擦除/推近为主，避免花哨转场。
- **数据色**：Before 用珊瑚红 `#FB7185`，After 用青绿 `#34D399`，中性数据用青 `#22D3EE`，地板线用灰紫虚线。
- **字体**：中文 `PingFang SC`；西文 `SF Pro Display / Helvetica Neue`；代码 `SF Mono / Menlo`。全部本机字体，渲染不依赖网络。
- **常驻 HUD**：左下 `DSH · FASTBOOT`，底部 2px 进度线，右上角章节编号；透明度低，不抢内容。

## 叙事结构

> 先让观众感到“慢”，再给一个反直觉的洞察，然后拆开机制，最后用同一张图表把收益钉死。

| 章节 | 时间 | 长度 | 作用 |
|---|---|---|---|
| S1 冷开场 | 0:00–0:08 | 8 s | 立住标题与核心数字 |
| S2 问题 | 0:08–0:22 | 14 s | 启动被 MCP 拖住 |
| S3 洞察 | 0:22–0:38 | 16 s | 串行 → 并发，MCP 移出关键路径 |
| S4 机制 A | 0:38–0:54 | 16 s | Loader 钩子 + 非阻塞 apply |

## S1 · 冷开场（0:00–0:08，0–240 帧）

**画面**

1. 0–20f：全黑，只有一颗青色光点在画面中心呼吸；点阵网格从中心向外淡入。
2. 20–80f：`DSH` 三个字母以 160ms 间隔从下方 40px 升起，带轻微模糊到清晰；字母间距从 0.4em 收紧到 0.12em。
3. 60–140f：主标题下方划出一条 1px 青线，向右生长；`FASTBOOT` 以等宽字体逐字打出，像终端。
4. 100–200f：副标题 `让你的 DSH 启动再快一点` 淡入；右上角出现计时器，数字从 `8.14s` 快速倒数到 `2.22s`，最后定格并闪一下青绿。
5. 200–240f：整屏轻微推近 4%，一条高光从左向右扫过标题，切黑进入 S2。

**文案**

- 主标题：`DSH FASTBOOT`
- 副标题：`让你的 DSH 启动再快一点`
- 角标：`MCP 加速 · 局部热重载 · 零配置`

**音效**：低频 whoosh 进入；标题落位时一声短促的合成 click；数字定格时的高频 ping。

## S2 · 问题：8 秒里，6 秒在等 MCP（0:08–0:22，240–660 帧）

**画面**

1. 240–330f：画面切成“启动时间轴”。左端 `process start`，右端 `Host ready`；一条灰色细线贯穿。
2. 300–420f：三个节点依次亮起：`配置合成 0.17s`、`Web 端口监听 1.53s`，然后时间轴突然“空”出一大段——用暗红色斜纹填充，标注 `等待插件 apply()`。
3. 420–660f：四张 MCP 卡片从时间轴下方浮起，按就绪时间排成阶梯：
   - `Cloudflare Docs` 2.19 s（HTTP 直连，最快）
   - `Cloudflare Bindings` 6.91 s（stdio / mcp-remote）
   - `Notion` 7.45 s（stdio / OAuth）
   - `Cloudflare Observability` 8.14 s（stdio / 最后就绪）
   每张卡片有 `connecting…` 呼吸点；Bindings 卡片闪一次红色 `retry`，对应“初次连接失败 1 轮”。第五个位置留给 `⋯`，表示服务器还会更多；右下角标注「每多一个 MCP，就多一段串行等待」。
4. 560–720f：底部终端条滚动：
   ```
   $ npx -y mcp-remote https://mcp.notion.com/mcp
   $ npx -y mcp-remote https://observability.mcp.cloudflare.com/mcp
   ... 6 次 npx 启动
   waiting for tools/list ...
   ```
   每出现一行，右上角计数器 `npx 6` 跳一下。
5. 700–820f：右侧浮出代码卡：
   ```ts
   // @deepseek-ai/dsh-mcp-client
   async apply(ctx) {
     await connection.ready      // ← 阻塞
     await syncTools()
   }
   ```
   `await` 被红框圈住，卡片整体轻微抖动。
6. 780–840f：8.14s 收束，画面切向 S3。

**旁白/字幕**

- `Cordis 会等每一个插件 apply() 完成，才宣布 Host 就绪。`
- `四个 MCP，四个网络握手；最慢的那个，决定所有人看到界面的时间。`
- `8.14 秒——这是四轮交替实测的中位数；最慢一轮 11.86 秒。`

**数据角标**：`DSH 0.2.2-rc.1 · Web profile · 暖缓存 · 4 轮交替 · 中位数`

## S3 · 洞察：把 MCP 从「后面」挪到「旁边」（0:22–0:38，660–1140 帧）

**画面**

1. 0–130f：串行链从 Web 开始，5 个 MCP 块依次落位（Docs / Bindings / Notion / Observability / `⋯⋯`），每块 `+1.32s`，Host 读数同步从 1.53s 推到 8.14s；省略号块表示「还有更多」。
2. 126f：8.14s 读数砸下，红色冲击波、屏幕震动、整屏红闪；左下的 `SERIAL COST` 面板同步累加 `1.53 + 6.61 = 8.14`。
3. 222–274f：5 张卡片整体从串行链坠落到下方并发车道，途中虚化、拉出速度线；顶部留下虚线 ghost 槽位，表示「原来的位置」。
4. 262f 之后：并发车道点亮。Web 1.53s 与 MCP 同时起跑；UI 在 2.22s 可用，MCP 继续到 4.20s；右侧 `CONCURRENT RESULT` 面板给出 2.22s / 4.20s / −72.7%。
5. 372f 起：底部大字 `8.14s → 2.22s` 定格。

**关键视觉**

- 串行：一条横向链，每块都在把红色终点线往右推——「每一项都在拖慢」。
- 并发：Web 与 MCP 两条上下并行的车道，UI 竖线在 2.22s 处截断，MCP 继续向后——「工具晚到，界面不等」。
- 省略号卡片 `⋯⋯` 明确表示服务器还会更多，但优化对任意数量成立。

**旁白/字幕**

- `串行时，每多一个 MCP，Host 就晚 1.32 秒。`
- `并发时，Web 和 MCP 一起跑；界面 2.22 秒可用，工具在后台继续。`

## S4 · 机制 A：在 Loader 导出阶段包一层（0:38–0:54，1140–1620 帧）

**画面**

1. 1200–1300f：架构图从左到右生长：
   `Cordis Loader` → `unwrapExports()` → `mcp-client plugin` → `apply()`。
   线和节点用描边动画绘制，节点落位有轻微回弹。
2. 1300–1450f：钩子插入。一个青色高亮环套住 `unwrapExports`，代码卡从节点下方展开：
   ```js
   const original = Loader.prototype.unwrapExports
   Loader.prototype.unwrapExports = function (exports) {
     const plugin = original.call(this, exports)
     if (plugin?.name === 'mcp-client') return wrap(plugin)
     return plugin
   }
   ```
   同时画面右侧出现 `wrapper` 盒子，把 `mcp-client` 包进去。
3. 1450–1600f：wrapper 内部放大，显示：
   ```js
   async apply(ctx, config) {
     patchSdk()                  // 先补 SDK
     void plugin.apply(ctx, config)  // 不 await
   }
   ```
   `void` 与“不 await”用青绿高亮；下方一条“启动主线程”继续向右跑，另一条“MCP 连接”向下分叉，形成并行双线。
4. 1600–1700f：右下角小字补充：`上游 effects / reconnect / dispose 仍在 apply 内注册，生命周期不受影响。`
5. 1700–1740f：并行双线同时到达终点，但 UI 线先亮；画面推入 S5。

**旁白/字幕**

- `不改上游代码：在插件导出时包一层，把 apply 变成“启动，但不等待”。`
- `连接、重连、释放仍由上游管理；只是不再挡住 Host。`

## S5 · 机制 B：少一次探测，少一次 npx（0:54–1:08，1620–2040 帧）

**画面**

1. 1740–1840f：左侧“Before”进程树：
   ```
   Host
    └─ npx mcp-remote
        ├─ server/discover  ← 短命探测进程
        └─ mcp-remote       ← 真正连接
   ```
   探测进程出现 300ms 后灰掉、打叉；再启动正式进程。右侧计数器 `npx 6`、`失败 1`。
2. 1840–1980f：右侧“After”进程树重写：
   ```
   Host
    └─ node ~/.npm/_npx/…/mcp-remote/dist/proxy.js
   ```
   `npx` 字样被划掉，替换为 `node`；探测进程直接不出现。计数器滚动：`npx 6 → 0`，`node 0 → 3`，`失败 1 → 0`。
3. 1980–2100f：两条补丁以代码卡呈现：
   ```js
   // stdio：显式 legacy 握手，跳过 server/discover
   client.setVersionNegotiation({ mode: 'legacy' })
   // 启动器：直接命中 npx 缓存里的入口
   params.command = process.execPath
   params.args = [cachedProxy, ...rest]
   ```
4. 2100–2220f：底部一行小字：`streamable-HTTP 保持现代协商，只获得后台启动。` 画面右侧 HTTP 卡片保持青色、不参与“降级”动画，形成对照。

**旁白/字幕**

- `stdio 服务器几乎都是 2025 协议；自动协商会先开一个探测进程，再开正式进程。`
- `fastboot 直接走 legacy 握手，并把 npx 换成缓存里的 node 入口。`
- `HTTP 服务器不动协议，只把连接放进后台。`

## S6 · 机制 C：改一行，只重载一个 entry（1:08–1:18，2040–2340 帧）

## 制作备注

- 所有数字统一四舍五入到 2 位小数展示，图表内部按原始值计算比例。
- `8.14` 与 `4.37` 是主结果；`2.22` 是后台原型的进一步结果，画面需明确标注“后台初始化”，避免与主结果混淆。
- 画面不出现“1.89s”等早期 staging 数字，避免与这份图表冲突；如需引用，放在口播之外的技术说明里。
- 视频无真人出镜、无外部素材；所有图形由 Remotion 代码绘制，可复现、可改数据。
